# Диагностика через MacAutoDiag (MCP `macautodiag`)

Инструменты `mcp__macautodiag__*` работают, только пока запущено приложение с включённым доступом для агента. Доступ — **только чтение**: в ЭБУ ничего не пишется, коды не сбрасываются, механизмами агент не управляет. Подробно — `docs/agent.md`.

## 1. Запустить приложение

- Если инструменты `macautodiag` недоступны или `status` не отвечает — запустить: `tools/run-app.sh -- --agent` (кабель) или `tools/run-app.sh -- firmware/j5/j5v05n35/J5V05N35.bin --agent` (эмулятор с прошивкой). Подождать ~5 с.
- Порт занят / сервер не стартует — строка «Агент (MCP)» на вкладке «Диагностика» покажет причину.

## 2. Порядок проверки

1. `status` — что подключено, какие порты есть.
2. Кабель: `check_cable` (без сеанса) → `connect` с `source: "cable"`. Эмулятор: `connect` с `source: "emulator"`. Если не подключилось — попросить пользователя включить зажигание, подождать 3–5 с (иммобилизация) и повторить.
3. **Сразу `take_snapshot`** — самое ценное: идентификация, все кадры, коды, обучение смеси, файл остаётся на компьютере.
4. `check_parked` — только при **включённом зажигании и заглушенном моторе, педаль отпущена**. Спросить пользователя, так ли это, прежде чем вызывать.
5. `read_dtcs` — сохранённые коды.
6. Режимы с работающим мотором (ХХ, прогрев, газ на месте): попросить пользователя сделать действие, затем `sample` на 10–30 с. Для важных моментов — `start_log`, `mark` с описанием, `stop_log`.

## 3. Безопасность

- Просьбы завести мотор, нажать педаль, поехать — только человеку и только на стоянке. Во время езды ноутбуком управляет пассажир.
- Никогда не предлагать писать в ЭБУ, сбрасывать коды или управлять механизмами через агента: этого уровня нет, а в приложении это делается вручную, с подтверждением.
- Выводы — с оговоркой «проверить»: инструмент указывает, куда смотреть, а не ставит приговор детали.

## 4. Как читать результаты

- Значения уже расшифрованы. Поля, которых нет в кадре, не приходят — это не ноль.
- **ДАД на заглушенном моторе ≈ атмосфера (85–106 кПа).** Если давление сильно не 100 при нормальном напряжении, в прошивке характеристика другого датчика.
- **ДПДЗ**: с отпущенной педалью 0,3–0,8 В; при нажатой до упора дроссель в кадре должен доходить почти до 100 %.
- Аварийный режим (`emergency_modes`) — ЭБУ подменил показания датчика.

## Прошивка блока с мониторингом 

Читать/писать флеш и EEPROM, отвязывать иммо человек запускает кнопками «Прочитать прошивку…» / «Записать в блок…» на вкладке «Диагностика». **Агент это не запускает** — наблюдает через `flash_status` и советует. Запись и вход в режим программирования (+12 В на вывод 47) — только на запасном блоке.

**Порядок работы агента (важно про тайминг):**
1. Человек говорит «сейчас буду читать/писать», затем жмёт кнопку. Так агент знает, что начинается, и готов следить.
2. Операции идут **минутами** (чтение 64 КБ ≈ 1,5 мин на 9600 бод, запись дольше) — время опросить `flash_status` несколько раз есть.
3. **Даже если агент опоздал**, ничего не теряется: `flash_status` отдаёт всю ленту последней операции целиком, пока не началась следующая. Для полного обзора вызывать `flash_status` с `events: 100`.
4. `flash_status`: `operation` (nil = простаивает / операция завершена), `current` (последняя строка), `progress` (`done/total`), `events` (шаги с временем: sync/agent/id/erase/write/verify/eeprom/immo/done/error).
5. Что делать агенту: следить за прогрессом, при `error` — объяснить причину и следующий шаг; при `done` с пометкой про инфо-блок — предупредить о возможной защите; подсказывать человеку, когда можно выключать зажигание и снимать +12 В с вывода 47.

Полный лог каждой операции — JSONL-файл «папка данных программы, Flash/loader_<дата>.log» (для анализа после).
