# План: запись логов и разбор для улучшения настройки

Задача (26.10.2026): приложение должно записывать лог показаний датчиков так, чтобы потом его можно было разобрать и понять, что улучшить в настройке автомобиля.

## Этап 6. Запись лога

### Сделано (26.10.2026)

- Код: `Sources/VazCore/Logging/SensorLog.swift` (`LogSchema`, `SensorLogWriter`), интерфейс — полоса записи на экране «Диагностика».
- Папка сеанса: `~/Documents/MacAutoDiag/Logs/<ГГГГ-ММ-ДД_ЧЧ-ММ-СС>_<ID ПО>/` (эмулятор) или `…_K-line/` (кабель; ID блока по кабелю не читается):
  - `log.csv` — заголовок `time_ms,<id каналов>,marker`; числа с точкой, флаги 0/1, слова неисправностей — 8 hex-цифр (`faults` = слова 1–4); метка — текст в кавычках в строке, следующей за нажатием;
  - `log.json` — описание сеанса: время начала, ID ПО, КС, источник (эмулятор/K-line), id расширенного кадра J5LS, список каналов с русскими названиями и единицами, метки с временем, число строк;
  - `firmware.bin` — образ, исполнявшийся в эмуляторе (для K-line появится, когда будет чтение прошивки).
- Каналы: 24 базовых (кадр `21 01`) + 23 J5LS (если ЭБУ отвечает на `21 8C/0D/0F`).
- Частота: ~5 строк/с с одним кадром (P3min 100 мс); с J5LS — два запроса на строку, ~3 строки/с при 10400 бод.
- Проверено: запись с эмулятора J5V05L19 — 61–68 строк за 11–13 с.
- Горячие клавиши (меню «Диагностика», работают при любом фокусе): ⌘R — начать/остановить запись, ⌘K — метка; ⇧⌘D — подключить. Все продублированы кнопками на экране. Метка была на ⌘M, перенесена 26.10.2026: ⌘M — системное «Свернуть окно». Автоматически нажатия проверить не удалось (нет прав «Универсального доступа» у автоматизации) — проверить руками.

**Коды обновляются сами** (26.10.2026): пока есть связь, сохранённые коды перечитываются каждые 5 с; в лог список пишется только при изменении. Время реакции прошивки (J5V05L19 в эмуляторе, тест `unpluggedSensorShowsUpWithinSeconds`): после «отсоединения» ДПДЗ (0 В) текущая неисправность «ДПДЗ: низкий сигнал» — через ~0,75 с, сохранённый код P0122 — через ~1,25 с; обрыв ДТОЖ (5 В) — так же, P0118. У J5LS не проверено.

**Коды неисправностей в логе** (26.10.2026): каждое чтение кодов (`18`) — при подключении, по кнопке «Прочитать», а если запись начата позже — в момент старта записи — сохраняется в `log.json` (`troubleCodes`: время и список «код описание (статус)») и меткой «коды: P0122 …» на шкале. Сброс кодов отмечается меткой «сброс кодов» и требует подтверждения. Текущие флаги неисправностей (4 слова кадра `21 01`) пишутся в каждой строке, колонка `faults`.

### План

**Что пишем**

- Базовый кадр `21 01` (все параметры с формулами из `kwp2000-j5.md`).
- Для J5LS — расширенный кадр `21 8C/0D/0F` (`j5ls.md`): **давление во впуске (ДАД)**, температура воздуха, AFR фактический (ШДК) и целевой, смещение УОЗ по детонации **по каждому цилиндру**, АЦП ДД по цилиндрам, фаза впрыска, точные обороты, топливо ускорнасоса, передача. Для машины с ДАД и ДТВ это главный источник данных.
- Флаги режимов и неисправностей — отдельными колонками-битами (ХХ, отсечка, обогащение, зона ДК, детонация…).
- Метки пользователя (кнопка/горячая клавиша «отметить момент» + текст: «провал при разгоне», «дёргается на 2-й»).

**Формат**

- **CSV** (UTF-8, `;`-разделитель не нужен — `,` и точка в числах): открывается в Excel/Numbers, MegaLogViewer, Python. Первая колонка — время от начала, мс; физические величины в единицах, не сырые байты.
- Рядом **JSON-описание сеанса**: дата, ID прошивки, КС, тип ЭБУ, конфигурация датчиков, частота опроса, версия приложения, **снимок осей и таблиц калибровок** на момент записи (чтобы потом связывать лог с ячейками именно той прошивки).
- Опционально — сырые кадры KWP (hex) в отдельном файле: можно пересчитать лог, если найдём ошибку в формулах.

**Частота**

- 10400 бод, P3min 100 мс → ~5–8 записей/с базового кадра. Поздние J5LS поддерживают быстрый обмен (до 62500 бод с подходящим адаптером) → 20+ записей/с. Частоту показывать в интерфейсе.

**Интерфейс**

- Кнопка «Запись» на экране диагностики, счётчик времени и размера, автосохранение кусками (не потерять лог при обрыве связи).
- Список сохранённых логов.

**Проверка без машины** — запись с эмулятора (демо-режим), подачей входов ползунками; позже — сценарии «пуск/прогрев/ХХ/разгон», когда эмулятор получит модель коленвала и двигателя.

## Этап 7. Разбор лога и рекомендации

### Сделано (26.10.2026): поправка топливной таблицы по коэффициенту коррекции

- Код: `Sources/VazCore/Logging/LogAnalysis.swift` (`SensorLog` — чтение `log.csv`/`log.json`; `FuelCorrectionAnalysis`), интерфейс — вкладка «Лог» (`LogAnalysisView.swift`), «Файл → Открыть лог для разбора…» (⇧⌘L) или `MacAutoDiag FW --log <папка сеанса>`. Тесты — `LogAnalysisTests`.
- Лог накладывается на **любую таблицу с двумя осями** открытой прошивки (описание L19 или карта CTP). Колонка лога для оси подбирается по её единицам: об/мин → `rpm_precise`/`rpm`, мг/такт → `cycle_air`, % ДЗ → `throttle`, кПа → `map_kpa` (расширенный кадр J5LS), °C → `coolant`.
- Каждая запись делится между 4 соседними ячейками **с весами билинейной интерполяции** — так, как прошивка сама читает таблицу.
- Учитываются только записи: двигатель прогрет (ТОЖ ≥ 75 °C), **регулирование по ДК** (`f_lambda`), нет отсечки и мощностного обогащения, **установившийся режим** (за последнюю 1 с дроссель изменился ≤ 3 %, обороты ≤ 250; нужно ≥ 0,5 с истории). Причины отброса показываются.
- В ячейке: среднее отклонение коэффициента от 1,0 (+ — ЭБУ добавлял топливо, карта бедная) и число записей. Поправка предлагается от 5 записей, ограничена ±25 %. Для таблиц AFR (имя/единицы «состав смеси», «воздух/топливо») значение **делится** на коэффициент, для остальных — умножается.
- «Применить к таблице» записывает поправки в открытую прошивку; они видны в редакторе (выделены), отменяются «Отменить изменения», КС пересчитывается при сохранении.
- Для J5LS с ДАД по умолчанию выбирается «Поправка циклового наполнения» по давлению — при импортированной карте V43. Эмулятор коэффициент не меняет (нет модели ДК) — интерфейс проверен на синтетическом логе.

**Оговорки (предположения):** коэффициент коррекции в кадре — мгновенная поправка регулятора; если блок дополнительно хранит обучение (флаг «сохранение обучения по ДК»), часть ошибки карты уже сидит в обучении и в коэффициент не попадает — перед логированием для настройки обучение лучше сбросить. Какая таблица «правильная» для поправки, зависит от прошивки: для серийной J5 с ДМРВ ошибка обычно в тарировке ДМРВ/производительности форсунок, а не в отдельной ячейке — разбор показывает картину, решение за настройщиком.

**Разбор без дампа** (типовая сетка): дампа прошивки может не быть, а настоящие сетки лежат в ПЗУ (`613C`, `5EF2/5EF4`) и по диагностике не читаются (`23` даёт только ОЗУ `FD00–FEFF`). Поэтому вкладка «Лог» работает и без прошивки: обороты — 16 узлов серийной J5 (600…7470), нагрузка — давление ДАД (`map_kpa`, от 20 кПа до ближайших 10 кПа над максимумом в логе, не меньше 100), если его нет — ЦН по серийной сетке 40…519 мг, иначе дроссель. Применять к таблице в этом режиме нельзя; когда будет дамп — открыть его и тот же лог. Тест — `genericGridWithoutFirmware`.

**Графики** (вкладка «Лог» → «Графики»): каналы по времени на общей оси, по графику на канал; метки пользователя — оранжевые вертикальные линии с текстом; курсор показывает значения всех выбранных каналов в один момент. Набор каналов запоминается. Длинные логи прореживаются до ~2000 точек на канал.

### Дальше по этапу 7

1. **Просмотр**: графики по времени с масштабированием и синхронным курсором, несколько параметров на одной шкале, метки пользователя на шкале; диаграммы рассеяния (например, AFR от давления).
2. **Карта посещённых ячеек**: сколько времени/записей приходится на каждую ячейку обороты × нагрузка — по осям *той же прошивки* (для J5LS — обороты × давление/дроссель). Показывает, где двигатель реально работает и где данных мало.
3. **Ошибка состава смеси по ячейкам** (главное для настройки топлива): AFR факт (ШДК) против AFR цели, только в установившихся режимах — отбрасываются переходные процессы (быстрое изменение дросселя/давления, обогащение при ускорении, прогрев, отсечка, первые секунды после пуска). Результат — карта поправок в % к топливной таблице с весом по числу точек → «применить к таблице» в редакторе с предпросмотром разницы.
4. **Детонация**: карта откатов УОЗ по ячейкам и по цилиндрам → рекомендация убрать угол в конкретных ячейках; цилиндр-«лидер».
5. **Холостой ход**: стабильность оборотов (разброс, ошибка регулирования), положение РХХ в зависимости от температуры, провалы при включении нагрузки.
6. **Пуск и прогрев**: время пуска, обороты и состав в первые секунды, обогащение по температуре.
7. **Отчёт**: список найденных проблем с привязкой к таблицам и ячейкам, ссылками на места в логе и предлагаемыми правками.

Применение рекомендаций — только через редактор с показом разницы и пересчётом КС. Для J5LS запись изменённой прошивки возможна лишь штатными средствами автора (привязка к ЭБУ, `j5ls.md`): приложение готовит изменения, а заливает их калибровщик или «Матрица».

## Зависимости

- Транспорт FTDI (этап 4, написан, ждёт кабель) — для реальных логов.
- Расширенный кадр J5LS — декодер (этап 4).
- Описание таблиц прошивки: импорт карты CTP (этап 2) и дамп прошивки — чтобы привязать ячейки лога к таблицам.
- ШДК есть не у всех. Поэтому для топлива основной метод — **коэффициент коррекции впрыска** (`inj_corr`, байт 18 кадра `21 01`; в J5LS — байт 18 расширенного кадра): в зоне регулирования по ДК (флаг `f_lambda`) ЭБУ сам подгоняет подачу, и среднее отклонение коэффициента от 1,0 по ячейке = ошибка базовой топливной карты в этой ячейке. Вне зоны ДК (мощностной режим, переходные) узкополосный ДК даёт только «богато/бедно» — там рекомендации качественные. Если позже появится ШДК — колонка `wb_afr` уже пишется.
