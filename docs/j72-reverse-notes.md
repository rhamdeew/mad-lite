# Январь 7.2 (I205DO54): заметки по разбору прошивки

Образ — `firmware/j72/i205do54/i205do54.bin`, 64 КБ, ID `I205DO54`, платформа `J7.2` (байт `0x6009`). Процессор тот же Siemens C509, что у Января 5.1. Названия таблиц сверены с XDF `i205do54.xdf` (cm_gt, 17.06.2011, репозиторий `cmgt/ecusystems`; локально `docs/vendor/`, в git не входит). Описание для редактора — `Sources/VazCore/Definitions/I205DO54.json`, собирается `tools/gen_j72_definitions.py`.

Уверенность в описании:

- **confirmed** — по коду видно, куда записывается результат (ячейка ОЗУ из кадра KWP).
- **likely** — имя взято из XDF, а размер и оси сошлись с тем, как прошивка читает адрес.
- **auto** — видна только форма, имени нет.

На живом блоке это не проверялось.

## Карта памяти

| Область | Что |
|---|---|
| `0x0000–0x5EFF` | код |
| `0x5F00–0x5FFF` | константы до заголовка (минимальный впрыск `5FA8` и соседние) |
| `0x6000–0x604F` | заголовок: `J7.2`, ID `I205DO54` по `0x6020` |
| `0x6050–0xAEDF` | калибровки. Верхняя граница — адрес процедуры 32-точечной интерполяции |
| `0xAEDF` | кривая на 32 точки (тело как J5 `A575`) |
| `0xAF07` | карта 16×16 (тело как J5 `A59D`, сверено 40 байт) |
| `0xAF7B` | 1D-интерполяция (как J5 `A611`) |
| `0xAF99` | похожая карта, но читает **XRAM** (`MOVX`), не прошивку. Это не калибровка |
| `0xB012` | кривая на 16 точек (как J5 `A6CD`) |
| `0xBE75` | список адресов кадра `21 01` |

Второй экземпляр сигнатуры карты по `0xAF99` — не код ПЗУ: там `MOVX` вместо `MOVC`.

## Оси

Регистры те же, что у J5V05L19.

| Регистр | Что | Как установлено |
|---|---|---|
| `54h` | обороты/30 | сетка `613C[54h]` → `57h` (код `0x2DEB`). Сами байты `613C` совпадают с J5V05L19, узлы те же: 600…7470 об/мин. В эмуляторе на 3000 об/мин сюда пишется `64h` (100), пока процедура `B48A` не обнулит ячейку |
| `57h`, `58h`, `59h` | индекс оборотов на 16 и 32 точки | из `613C` |
| `5Ch`, `5Dh` | индекс нагрузки | карты вызываются как `R2=57h`, `R3=5Ch` |
| `52h` | дроссель, % | `7208[52h]` — индекс строки карт «обороты × дроссель» |
| `4Eh` | индекс температуры ОЖ, 0…36 | `(49h+2)/5` или `(49h+3)/5`, не выше 36 (код `0x37CA`, `0x2941`). Ось кривых: −40 °C, шаг 5 |
| `49h` | ТОЖ для кадра, °C = E−40 | пишет характеристика ДТОЖ `6104` |
| `60h` | желаемый AFR | карты `6613`, `6953` |
| `62h` | УОЗ, в кадре E/2 | карты `6AC8`, `6CC8`, `6DC8`, `7877` |

Нагрузка считается той же формулой, что в J5: узел `k` = `(смещение + k·шаг·2048/коэффициент) / 6`. Смещение — слово `6064` (у I205DO54 это 175, младший байт первый), коэффициент — байт `6066` (195). В XDF та же формула записана приближённо (`341.13` вместо `2048/6`).

### Сетка оборотов 30 / 40 об/мин: прошивки `*_fast` (27.10.2026)

В архиве пользователя есть серийные J7.2 «с изменённой таблицей квантования оборотов до 10200 об/мин» (`i203el36_fast`, `i204dm53_fast`, `i205dm53_fast`, `i226fm10_fast`; файлы в проект не брались). От серийных они отличаются ровно в 2 байтах кода (плюс байт `0006` 00→FA и КС): в двух местах `mov a,54h` заменено на `mov a,55h`. Так в J7.2 подтверждается то же, что в J5: `54h` = обороты/30, `55h` = обороты/40. 256 × 40 = 10240 об/мин — отсюда «до 10200».

| Прошивка | Место 1 (`605C` → `B`, затем `mov a,54h`) | Место 2 (`mov dptr,#613C; mov a,54h; movc` → `57h`) |
|---|---|---|
| I205DM53 | `1E47` | `2EB6` |
| I203EL36 | `1D36` | `2CE5` |
| I204DM53 | `1DB7` | `2E9B` |
| I205DO54 (то же место по коду, не патч) | `1E67` | `2DEE` |

Место 2 — это та сетка `613C[54h] → 57h`, что в таблице «Оси». Что делает место 1 (умножение на `605C`), не разбиралось. Что значит байт `0006 = FA`, тоже не разбиралось (вектор прерывания там не используется — предположение).

## Таблицы, прослеженные по коду

| Адрес | Что делает прошивка | Имя |
|---|---|---|
| `613C` | 256 байт, индекс оборотов | Сетка оборотов |
| `7208` | 101 байт, индекс дросселя | Сетка дросселя |
| `6104` | 32 точки по АЦП, результат − 20 → `49h`. В ячейке T+60 | Характеристика ДТОЖ |
| `6613` | ячейка 16×16 без интерполяции → `60h` | Состав смеси, экономичный режим. Масштаб 14,7·(E+128)/256 |
| `6953` | интерполяция → `60h` | Состав смеси, мощностной режим |
| `6AC8` | интерполяция → `62h`, если нет флагов ДМРВ | УОЗ, экономичный режим. E/2 градусов. Первая ячейка 21,5° |
| `6CC8` | интерполяция → `62h` | УОЗ в зоне ДК |
| `6DC8` | интерполяция → `62h` | УОЗ, мощностной режим |
| `7877` | то же, когда установлен `23h.6` или `24h.6` | УОЗ при неисправности ДМРВ |
| `726D` | столбец — обороты, строка — дроссель (`0x176A`) | Цикловое наполнение при аварии ДМРВ. Масштаб XDF ×8/3, мг/цикл |
| `9D3C` | интерполяция обороты×нагрузка → байт `52h` | Замена положения ДЗ |

`6BC8` картой УОЗ **не является** (в J5 по этому адресу была вторая карта угла). Здесь прошивка читает оттуда слово.

Адреса `613C 6104 6613 6713 6953 6AC8 6CC8 6DC8 726D 7877 75EF 7208 6813 8E2A` загружаются командой `MOV DPTR` в **каждом** сыром образе J7.2 из `firmware/j72/` (29 файлов, тест `everyRawImageLoadsTheSameMaps`). Полное описание JSON при этом привязано только к `I205DO54`: у других версий состав соседних таблиц может отличаться.

## Откуда имена

452 таблицы: 10 confirmed, 403 likely, 39 только с формой. Имена likely — из XDF, если размер совпал с кодом. Категории внутри XDF **нельзя** брать как группы: карты УОЗ там лежат в категории «Отключение топливоподачи», аварийный УОЗ — в «Регистраторе». Группы в нашем JSON собраны по названию.

XDF один раз называет один и тот же адрес по-разному (`63D3` — четыре названия, `7AC7` — два). В описании оставлено первое, остальные — в примечании.

Замечания, где название XDF расходится с вызовом:

- `6713` в XDF — «коэффициент от ТОЖ», по коду это карта 16×16, результат в XRAM `FF4F`, не в байт AFR.
- `8E2A` после интерполяции ограничивается `0x0F…0xF0` и пишется в `4Fh`. Масштаб (E+128)/256, как у коэффициента впрыска, но это не байт `6Fh` кадра.

Ручки заголовка (`0x6000–0x604F`) в таблицы не входят. Слово `6064` (минимум наполнения для сетки) — little-endian: байты `AF 00` = 175, делённые на 6 дают ≈29 мг/цикл. Старшим байтом вперёд получилось бы бессмысленное число.

## Кадр диагностики

См. `docs/kwp2000-j5.md`, раздел «Январь 7.2». Коротко: порядок и формулы байт `21 01` те же, напряжение ДК берётся из `F964` вместо `F815`, в конце лишнее слово `F93B` (что это — не установлено).

В эмуляторе кадр отвечает (KeyBytes `6B 8F`, декодер J5 разбирает ответ). На 1,9 с при колесе 3000 об/мин байт `55h` равен `4Bh` (3000). На 3,7 с процедура `B48A` обнуляет обороты, и дальнейшие опросы видят 0. Живой блок не снимался. Подробности — `docs/emulator.md`.

## Что не сделано

- Двигатель в эмуляторе не остаётся заведённым: обороты появляются и стираются. Демо-режим приложения для 7.2 из-за этого не включён.
- Описание не распространено на остальные ID, хотя 14 основных адресов общие.
- Слово `F93B` и назначение `6713` дальше записи в `FF4F` не прослежены.
